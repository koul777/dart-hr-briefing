# 발표자 노트 — DART로 HR Analytics 에이전트 만들기

## 운영 원칙
- 슬라이드 설명은 전체 시간의 20%를 넘기지 않습니다.
- 각 모듈은 설명 → 강사 시연 → 참가자 재현 → 통과 확인 → 저장 순으로 진행합니다.
- 정시 통과율이 80% 미만이면 새 설명을 멈추고 검증된 복구본으로 전환합니다.
- 실제 직원·지원자 개인정보는 어떤 단계에서도 입력하지 않습니다.

## 슬라이드별 진행
### 01. 오프닝 2분
완성 결과를 예고하고 오늘의 질문을 던집니다.

### 02. 문제 제기 2분
인당 생산성 계산 예시로 공시 데이터가 HR 질문으로 바뀌는 장면을 설명합니다.

### 03. 완성본 시연 3분
기업 선택, Compare, Strategy, AI 질문을 끊지 않고 보여줍니다.

### 04. 산출물 약속 2분
수강생이 제출할 네 가지 결과물을 명확히 말합니다.

### 05. 시간표 2분
체크포인트 시각과 80% 전환 규칙을 공지합니다.

### 06. Starter 방식 2분
전체 코드를 처음부터 작성하지 않는 이유와 네 가지 직접 구현 범위를 설명합니다.

### 07. 사전점검 2분
FAIL 0만 확인하고 키 값은 절대 화면에 띄우지 않습니다.

### 08. 구조 지도 3분
다섯 파일 위치를 실제 편집기에서 열어 보여줍니다.

### 09. 모듈 1 시작
m1 완료 상태를 다시 읽습니다.

### 10. 역할 경계 3분
AI에게 맡길 일과 사람이 검증할 일을 수강생에게 한 가지씩 말하게 합니다.

### 11. 프롬프트 01 실습 5분
출력에서 파일 경로 다섯 개를 찾게 합니다. 수정 제안이 나오면 아직 적용하지 않습니다.

### 12. 프롬프트 구조 3분
목적·입력·규칙·완료기준 중 빠진 항목을 찾게 합니다.

### 13. 합성 샘플 3분
SAMPLE 배너와 외부 호출 없음 상태를 확인합니다.

### 14. 프롬프트 02 실습 15분
계획 확인 후 변경을 적용하고 브라우저에서 직접 조건을 바꿉니다.

### 15. m1 점검 5분
통과율을 집계하고 미완료자는 작업 폴더를 보존한 채 복구본으로 이동합니다.

### 16. 모듈 2 시작
API 호출보다 데이터 정의가 먼저라는 메시지를 강조합니다.

### 17. OpenDART 흐름 3분
corp_code와 종목코드의 차이를 설명합니다.

### 18. 데이터 정의 4분
연결·별도, 기준일, 단위가 다른 값의 직접 비교를 금지합니다.

### 19. 키 경계 3분
env 파일과 공개 가능한 예시 파일의 차이를 보여줍니다.

### 20. 프롬프트 03 실습 15분
결측을 0으로 치환하지 않았는지 코드와 화면에서 확인합니다.

### 21. 기업 검색 4분
삼성전자 검색 결과에서 법인명·종목코드·DART 식별자를 확인합니다.

### 22. 비교 조건 4분
기업·연도·보고서가 결과와 함께 보이는지 확인합니다.

### 23. m2 점검 5분
키 오류나 429가 반복되면 즉시 합성 복구 데이터로 전환합니다.

### 24. 모듈 3 시작
조회와 분석의 차이를 예고합니다.

### 25. 파생지표 5분
계산식 네 개를 설명하고 결측·분모 0 조건을 묻습니다.

### 26. 프롬프트 04 실습 12분
함수와 테스트를 함께 만들고 정상·결측·0 사례를 실행합니다.

### 27. AI 입력 계약 3분
원문 전체가 아니라 서버가 검증한 JSON을 전달하는 이유를 설명합니다.

### 28. 챗봇과 Agent 3분
도구 호출과 검증 루프가 Agent의 핵심임을 설명합니다.

### 29. 프롬프트 05 실습 10분
사실·계산·해석·추가 확인 구분과 금지 규칙을 적용합니다.

### 30. Strategy Brief 4분
ready의 의미가 성공확률이 아님을 확인합니다.

### 31. 후속 질문 4분
두 기업의 생산성 차이를 묻고 근거 ID와 한계를 찾습니다.

### 32. m3 점검 5분
AI 장애는 실패가 아니라 대체 응답 검증 경로로 평가합니다.

### 33. 모듈 4 시작
저장소와 공개 URL을 최종 산출물로 다시 확인합니다.

### 34. 업로드 전 점검 3분
git add 전에 .env, 비밀값, 로컬 산출물이 제외됐는지 확인합니다.

### 35. GitHub 저장소 생성 3분
github.com/new에서 초기 파일을 추가하지 않은 빈 저장소를 만들게 합니다.

### 36. GitHub 첫 푸시 6분
명령을 한 줄씩 실행하고 status, remote, main → main을 확인합니다.

### 37. GitHub 웹 확인 2분
README, vercel.json, 최신 커밋을 확인하고 .env가 없는지 검사합니다.

### 38. Vercel Git 연결 3분
vercel.com/new에서 GitHub 권한과 저장소 Import까지 진행합니다.

### 39. Vercel 프로젝트 설정 3분
Framework Other, Root ./, Build/Output 기본값을 확인합니다.

### 40. Vercel 환경변수 4분
변수 이름과 대상 환경만 함께 확인하고 실제 키 값은 화면에서 가립니다.

### 41. Vercel Deploy 3분
Building에서 멈추면 Build Logs의 첫 번째 오류를 읽게 합니다.

### 42. 운영 검증 4분
root, health, 합성 샘플을 같은 Production URL에서 재현합니다.

### 43. 자동 재배포 2분
기능 브랜치와 main의 Preview·Production 차이를 설명합니다.

### 44. 배포 복구 2분
저장소 권한, 인증, 로그, 환경변수, route 중 증상에 맞는 한 곳만 봅니다.

### 45. m4 점검 3분
GitHub URL과 Vercel URL을 짝과 교환하고 합성 샘플을 실행합니다.

### 46. 마무리 2분
네 결과물을 함께 읽고 다음 주 합성 내부 데이터 설계로 연결합니다.
