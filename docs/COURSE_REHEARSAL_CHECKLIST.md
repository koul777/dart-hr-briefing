# DART HR Briefing 4시간 강의 드레스리허설 체크리스트

이 문서는 강사가 실제 수업과 같은 조건에서 `m0`부터 `m4`까지 4시간 골든패스를 재현하고,
진행률·장애 전환·최종 증거를 한 번에 기록하기 위한 실행표다. 운영 기준은
[강사용 런북](INSTRUCTOR_RUNBOOK.md), [참가자 사전점검](PARTICIPANT_PREFLIGHT.md),
[PPT 정렬 계획](PPT_ALIGNMENT_PLAN.md)과 일치시킨다.

리허설 대상은 **본문 42장·부록 18장·총 60장** 편성이다. 본문 42장만 4시간 타임박스로 재생하고,
부록 18장은 질문·장애 복구 때만 연다.

## 즉시 중단 안전 게이트

다음 중 하나라도 발견되면 현재 화면 공유·녹화·제출을 중단하고 해당 산출물을 배포하거나 커밋하지
않는다.

- `.env`, API 키, gateway token, Authorization 헤더, 쿠키 또는 비밀값이 화면·로그·URL·캡처에 보임
- 실제 직원·지원자의 이름, 연락처, 이메일, 사번, 이력서, 평가·보상·건강·노조 정보가 입력됨
- AI가 근거 없는 수치, 개인 평가, 보호특성 판단, 자동 채용·보상·감축 조치를 그대로 표시함
- 합성 수치를 실제 기업 수치로 소개하거나 SAMPLE 화면을 OpenDART 원문 증거로 사용함
- 원격 저장소 소유권이나 배포 대상을 확인하지 않은 상태에서 push 또는 production 배포를 시도함

비밀값이 노출되면 값을 다시 읽거나 채팅에 복사하지 않는다. 캡처·녹화를 폐기하고 해당 키를
폐기·재발급한 뒤 처음부터 민감정보 검사를 다시 수행한다. 실제 개인 데이터가 입력되면 해당 입력과
파생 산출물을 삭제하고 합성 사례로 교체한다.

## 사람/AI 역할 경계

- **사람의 역할**은 입력 범위 선택, AI 전송 동의, 공시 원문·근거 확인과 최종 판단 책임이다.
- **AI의 역할**은 공개 기업 단위 집계의 근거 있는 요약·해석 초안이다. 개인 평가, 인과 단정,
  자동 채용·승진·보상·감축 등 자동 인사조치를 결정하거나 권고하지 않는다.
- 리허설 통과는 AI 답변 생성 여부가 아니라 근거 ID·한계·사람의 검증 행동·연결 해제 증거로 판정한다.

## 80% 진행률 전환 규칙

1. 분모는 해당 체크포인트에 참여 중인 인원이다. 사전에 승인된 관찰자와 이미 사후 과제로 전환된
   인원은 분모에서 빼고, 제외 사유를 기록한다.
2. 통과 인원은 아래 화면별 **통과** 열의 객관적 증거를 보인 인원만 센다. “거의 됨”은 통과가 아니다.
3. T-5분에 조교가 `통과 / 진단 중 / 복구본 / 권한·외부 장애` 네 상태를 집계한다.
4. 정시 통과율이 80% 이상이면 통과자는 다음 단계로 이동하고 나머지는 조교와 복구본을 사용한다.
5. 정시 통과율이 80% 미만이면 강사는 새 설명과 라이브 호출을 멈춘다. 전체가 5분 대체 경로를
   수행한 뒤 같은 통과 기준을 다시 확인한다.
6. OpenDART·AI·GitHub·Vercel처럼 공통 외부 장애가 참가자의 20%를 넘으면 개인 오류로 취급하지
   않고 즉시 전체 대체 경로로 전환한다.
7. m4 배포가 16:40까지 끝나지 않으면 기능 검증은 D-1에 확인한 강사 배포 또는 짝의 검증된 배포로
   수행하고, 개인 배포는 사후 과제로 남긴다.

## 장애 전환 리허설

정상 경로 뒤 아래 장애를 하나씩 강제로 가정한다. 실제 production 장애를 만들거나 키를 망가뜨리지
말고, 로컬 결정론적 harness·네트워크 차단·권한 없는 테스트 계정처럼 되돌릴 수 있는 방법을 쓴다.

| 장애 | 관찰할 신호 | 허용 재시도 | 5분 대체 경로 | 복귀 기준 | 완료 |
| --- | --- | ---: | --- | --- | --- |
| 8765 점유·다른 `dart` 실행 | 다른 app ID 또는 바인딩 실패 | 1회 | 실제 대체 포트 또는 검증 실행 파일 | root와 health가 같은 앱 ID | [ ] |
| OpenDART timeout·429 | browser 45초 timeout 또는 안전한 오류·request ID | 최초 요청 포함 최대 3회(재시도 최대 2회) | 합성 fixture와 준비된 공개 공시 화면 | 강사 PC 단일 요청 성공 | [ ] |
| 조건 변경 중 응답 | 이전 compare/strategy/AI 요청 진행 중 | 재시도 없음 | 새 조건에서 다시 실행 | stale 결과가 새 조건을 덮지 않음 | [ ] |

client timeout에 request ID가 없으면 임의로 만들지 않는다. 서버가 반환한 request ID만 조교에게
전달하며, 내부 예외·키·요청/응답 원문은 공유하지 않는다.
